# Integration

A new tool shouldn't mean a new way of working. Our work on integration is about fitting into the tools a team already uses, so what our systems understand shows up where the work happens and nobody has to stop and switch.

## What we're exploring

- **Planning.** Laying issues out on a shared timeline that product, design and engineering all read from.
- **Issues from the code.** Writing issues that cite the files and lines behind them, and linking a new report to one you already have.
- **Coding agents.** Giving your coding agent the same understanding over MCP, so it starts from the right files.
- **Keeping up.** Re-reading a repository on every push, so plans and answers stay in step with the code.

## Where it shows up

[Ucelot](/products/ucelot) brings these together: issues, planning and agent access, built on its understanding of your repositories and documents.
